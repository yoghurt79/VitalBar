# VitalBar
# 元气条 VitalBar

> 一款基于 Electron、React 和 TypeScript 的本地离线自律打卡桌面应用。它把用户每天手动记录的学习、健身、熬夜等行为，转换为健康值、心情倍率、长期经验、等级称号和元气币，并通过日历、趋势报告和奖励系统，让自律过程变得可见、可反馈、可持续。

## 项目简介

元气条不是一个自动监控用户隐私的软件，而是一个遵循“用户主动记录、系统自动计算”理念的本地自律工具。

用户只需要在完成行为后手动选择对应行为，应用便会根据当前状态自动结算：

- 健康值变化
- 心情值变化
- 长期自律经验
- 自律等级和称号
- 元气币奖励
- 周、月、年度统计数据
- 基于本地规则生成的可执行建议

应用运行时不需要网络。账户、行为记录、商店购买和设置默认只保存在本机。


## 核心特色

### 1. 主动记录，不做隐私监控

应用不会自动读取屏幕、视频播放记录、游戏记录或睡眠数据，也不会检测用户是否真的熬夜。用户完成行为后主动打卡，应用只负责按照公开规则计算。

### 2. 短期状态与长期成长分离

健康值和心情值代表短期状态：

- 健康值会随正向和负向行为升降
- 心情值会影响健康收益和损失倍率

长期经验代表累计成长：

- 正向行为增加经验
- 负向行为不会扣除历史经验
- 等级不会因为一次负向行为而下降
- 等级提升后逐步解锁称号

### 3. 情绪倍率机制

心情值不是单纯的装饰数据，它会直接改变行为收益。

- 心情越好，正向行为获得的健康值越多
- 心情越好，负向行为造成的健康损失越少
- 心情越低，正向收益越少，负向损失越大
- 心情触底不会阻止用户打卡

### 4. 成长反馈闭环

正向行为带来的有效健康值会转换为经验和元气币。

元气币可用于兑换：

- 头像框
- 徽章
- 空间装饰
- 商店专属称号

目标是把“自律”和“娱乐奖励”连接起来，形成正向循环。

### 5. 本地报告与可视化

应用会把所有记录汇总为：

- 现实日历热力图
- 每日签到对勾
- 周报
- 月报
- 年度报告
- 健康趋势图
- 最大增益行为
- 最大损耗行为
- 当前状态下的行动建议


## 功能详情

### 手动行为打卡

默认支持六类行为：

| 行为 | 健康值 | 心情值 | 类型 |
|---|---:|---:|---|
| 熬夜 | -100 | -20 | 负向 |
| 学习 | +30 | -20 | 正向 |
| 健身 | +20 | -10 | 正向 |
| 长时间打游戏 | -30 | +10 | 负向 |
| 长时间刷视频 | -20 | +10 | 负向 |
| 不控制饮食 | -10 | +20 | 负向 |

### 等级与称号

等级经验按约 1.9 倍递增：

| 等级 | 称号 | 累计经验门槛 |
|---:|---|---:|
| Lv.0 | 初醒 | 0 |
| Lv.1 | 微光 | 200 |
| Lv.2 | 节律 | 580 |
| Lv.3 | 自律者 | 1302 |
| Lv.4 | 掌控者 | 2674 |
| Lv.5 | 元气大师 | 5281 |

成长规则：

- 正向行为的有效健康值会增加长期经验
- 负向行为不会扣除长期经验
- 等级不会下降
- 等级越高，称号卡片的视觉表现越丰富

### 心情与健康倍率

| 心情值 | 正向健康收益 | 负向健康损失 |
|---:|---:|---:|
| 0 | ×0.5 | ×2.0 |
| 1–29 | ×0.5 | ×1.5 |
| 30–60 | ×1.0 | ×1.0 |
| 61–99 | 从 ×1.0 递增至接近 ×2.0 | 从接近 ×1.0 递减至接近 ×0 |
| 100 | ×2.0 | ×0 |

心情为 0 时：

- 心情不会继续变成负数
- 正向行为仍可按 ×0.5 获得健康值
- 健身、学习等行为不会被阻止
- 负向行为仍然按 ×2.0 计算健康损失

### 元气币

- 只有正向有效健康值会产生元气币
- 元气币奖励约为有效健康值的 50%
- 负向行为不会增加元气币
- 元气币可用于商店兑换
- 商品购买后永久归属于当前本地账户

### 元气商店

当前商店包含：

- 头像框
- 徽章
- 空间装饰
- 商店专属称号

商店物品全部使用代码绘制，不依赖在线图片。

支持：

- 查看商品价格与说明
- 购买并自动装备
- 商店专属称号展示
- 头像框、徽章和装饰装备
- 根据用户等级和签到数据形成长期收集目标

### 日历热力图

- 使用现实年份和月份
- 每天有记录时显示签到对勾
- 当天健康值越高，蓝色越明显
- 当天健康值为负时显示暖色
- 点击日期可以查看当天行为明细
- 支持查看前一个月和后一个月
- 支持一键回到本月
- 未来日期不可点击

### 数据报告

支持三种报告周期：

- 周报
- 月报
- 年度报告

报告内容：

- 健康净变化
- 正向健康总量
- 负向健康总量
- 心情净变化
- 元气币获得量
- 签到天数
- 行为次数
- 平均每日健康变化
- 增益最多的行为
- 健康值杀手
- ECharts 趋势柱图
- 本地规则建议

### 本地智能建议

项目的“智能建议”不调用云端模型，而是根据本地数据生成确定性的规则建议。参考因素包括：

- 当前心情值
- 当前健康值
- 最大健康损耗行为
- 最大正向收益行为
- 正负行为总量对比
- 本期签到是否存在


### 提醒与系统托盘

- 默认早间提醒：09:00
- 默认晚间提醒：21:00
- 提醒时间可修改
- 使用 Windows 原生通知
- 支持关闭窗口后驻留系统托盘
- 托盘菜单支持重新打开和完全退出
- 支持设置开机自动启动

提醒依赖应用或托盘进程运行。完全退出应用后，提醒会停止。


## 每日唯一打卡规则

每种行为按照“用户 + 现实日期 + 行为类型”限制为每天一次。

界面会对已完成行为显示“今天已完成”，并禁用按钮。即使绕过界面直接调用数据层，重复记录也会被拒绝。

第二天现实日期改变后，所有行为重新恢复可打卡状态。

### 安全边界

渲染层不能直接访问 Node.js 或文件系统。Electron 使用：

- `contextIsolation: true`
- `nodeIntegration: false`
- `sandbox: true`
- preload 白名单 API
- IPC 主进程处理

数据流：

```text
React 页面
   ↓
preload API
   ↓
ipcRenderer.invoke
   ↓
Electron 主进程
   ↓
本地 Store
   ↓
vitalbar-store.json
```

## 本地数据与隐私

默认数据由 Electron 的 `userData` 目录保存，文件名为：

```text
vitalbar-store.json
```

也可以通过环境变量指定测试数据目录：

```powershell
$env:VITALBAR_DATA_DIR="D:\VitalBarData"
```

数据包含：

- 用户名
- 密码哈希与盐
- 当前健康值
- 当前心情值
- 元气币
- 长期经验
- 已购买商品
- 行为记录
- 提醒设置

不会包含：

- 明文密码
- 云端账户 Token
- 设备定位
- 摄像头或麦克风数据
- 自动采集的浏览、游戏或睡眠记录

## 开发环境

建议环境：

- Windows 10/11
- Node.js 22.12 或更高
- pnpm 11

安装依赖：

```powershell
pnpm install
```

如果 Electron 官方下载源连接失败，可以使用镜像：

```powershell
$env:ELECTRON_MIRROR="https://npmmirror.com/mirrors/electron/"
pnpm install
```

## 当前边界

- 当前主要面向 Windows 打包和测试
- 不提供跨设备云同步
- 不调用在线大模型
- 不自动监控用户行为
- 不提供医学诊断或治疗建议
- 完全退出应用后不会继续运行提醒

Windows 首次运行未签名程序时可能出现 SmartScreen 提示。用户确认来源后可以选择“更多信息”并继续运行。
